# Переход на PostgreSQL

## Цель

Заменить SQLite на PostgreSQL для состояния приложения, сохранив историю, лимиты и возможность запуска как локально, так и в Docker Compose.

## Подход

Использовать PostgreSQL и драйвер psycopg, переписать SQL и настройки приложения. Альтернатива — сохранить два движка или внедрить ORM: первая увеличивает объём поддержки и оставляет SQLite в рабочем пути, вторая требует более широкой переработки. Прямой переход соответствует запросу пользователя.

## Хранение и запуск

- Добавить PostgreSQL в Compose с постоянным томом, healthcheck и зависимостью приложения от готовности базы. Доступ с хоста ограничить loopback; учётные данные задаются конфигурацией, не фиксируются в репозитории.
- Приложение подключается по DATABASE_URL; для локального запуска используется адрес localhost, для контейнера — имя сервиса Compose. Обновить мастер настройки, пример окружения, инструкции и Docker-конфигурацию.
- Инициализация создаёт PostgreSQL-схему. SQL, параметры, идентификаторы, транзакции и обработка строк переводятся на PostgreSQL.
- Заменить локальную блокировку процесса на блокировку, действующую для процессов, подключённых к одной базе, включая локальный и контейнерный запуск. Не раскрывать учётные данные базы в логах.

## Перенос данных

- Предоставить отдельную явную команду переноса из существующего agent.db в пустую PostgreSQL-базу; не выполнять перенос автоматически при запуске.
- Читать SQLite без изменения исходного файла; переносить все таблицы и значения, включая историю откликов, неопределённые отправки, лимиты LLM и зашифрованные ключи Mistral. Сохранить идентификаторы и скорректировать последовательности PostgreSQL.
- Перенос делать одной транзакцией, проверять схему и количество записей, отказывать при непустой целевой базе. Существующий SQLite-файл сохранить; для ключей Mistral необходим прежний мастер-ключ.
- Выполнять перенос при остановленном агенте. До повторных откликов пользователь проверяет на HH неопределённые отправки, возникшие до переноса.

## Безопасность и проверка

- Транзакционно сериализовать конкурирующие резервирования дневных лимитов, выдачу и использование разрешений на отклик; проверять ограничение на реальной PostgreSQL при параллельных запросах.
- Проверить перенос данных, восстановление после прерывания, повторный запуск, блокировку экземпляров, и работу локальной и Compose-конфигураций. Тесты не отправляют реальные отклики и не используют рабочие учётные данные.
- Не утверждать, что PostgreSQL устранит причину предыдущей ошибки SQLite: причина не установлена.
